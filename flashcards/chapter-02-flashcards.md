## Chapter 2: Prompting, Model Selection, and LLM Limitations — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Zero-shot vs few-shot prompting — key difference? | Zero-shot: no examples given, model relies only on instructions. Few-shot: prompt includes labeled example input/output pairs to guide format/behavior. Exam tip: few-shot generally improves consistency for structured output tasks. |
| 2 | Role of the system prompt vs user prompt | System prompt: sets persona, tone, persistent rules/constraints for the whole conversation. User prompt: the specific question or task input. Exam tip: exam scenarios test where instructions belong. |
| 3 | Effect of lowering the temperature parameter? | Lower temperature (closer to 0) = more deterministic, repeatable, focused output. Higher temperature = more random/creative output. Exam tip: use low temperature for factual/extraction tasks, higher for creative generation. |
| 4 | Model size vs latency/cost tradeoff (e.g., 8b vs 70b vs 405b class models on Cortex) | Smaller models = lower latency, lower credit cost, less reasoning capability. Larger models = higher latency/cost, better complex reasoning and accuracy. Exam tip: match model size to task complexity, not always 'biggest is best'. |
| 5 | What is hallucination in LLMs? | When a model generates confident, plausible-sounding but factually incorrect or fabricated content. Exam tip: hallucination is an inherent limitation, not fully eliminated by any single model or parameter. |
| 6 | Best mitigation strategy for hallucination and knowledge-cutoff limitations? | Retrieval-Augmented Generation (RAG) — ground the model with relevant, current documents (e.g., via Cortex Search) injected into the prompt at query time. Exam tip: RAG is the standard answer for both hallucination and recency issues. |
| 7 | What is an LLM 'knowledge cutoff'? | The point in time after which the model has no training data, so it cannot know about events/facts after that date unless given external context. Exam tip: knowledge cutoff is a fixed limitation, not solved by prompting alone. |
| 8 | Why are LLMs considered non-deterministic? | Sampling-based generation (controlled by temperature/top_p) means the same prompt can yield different outputs across calls unless temperature is set very low/zero. Exam tip: non-determinism is expected behavior, not a bug. |
| 9 | Basic syntax to call an LLM in Snowflake Cortex | SELECT SNOWFLAKE.CORTEX.COMPLETE('<model_name>', '<prompt_text>'); Exam tip: model name is passed as a string literal; function returns generated text. |
| 10 | When should you pick a smaller Cortex-hosted model over a larger one? | When the task is simple (classification, short summarization, FAQ), high call volume, and latency/cost matter more than maximum accuracy. Exam tip: 'best fit for task', not 'biggest available', is the correct exam answer pattern. |
| 11 | temperature vs top_p — what do they control? | temperature: scales randomness of token probability distribution. top_p (nucleus sampling): restricts sampling to the smallest set of tokens whose cumulative probability exceeds p. Exam tip: both influence randomness but via different mechanisms — don't confuse them. |
| 12 | What does max_tokens control in a Cortex COMPLETE call? | The maximum length (in tokens) of the generated output. Exam tip: setting it too low can truncate answers mid-sentence; too high increases cost/latency unnecessarily. |
