## Embeddings & Vector Search on Snowflake — Cheat Sheet

### Core Functions
| Function | Purpose | Signature |
|---|---|---|
| `SNOWFLAKE.CORTEX.EMBED_TEXT_768` | Generate 768-dim embedding | `EMBED_TEXT_768(model, text)` |
| `SNOWFLAKE.CORTEX.EMBED_TEXT_1024` | Generate 1024-dim embedding | `EMBED_TEXT_1024(model, text)` |
| `VECTOR_COSINE_SIMILARITY` | Similarity (higher = closer) | `VECTOR_COSINE_SIMILARITY(v1, v2)` |
| `VECTOR_L2_DISTANCE` | Distance (lower = closer) | `VECTOR_L2_DISTANCE(v1, v2)` |
| `VECTOR_INNER_PRODUCT` | Dot product similarity | `VECTOR_INNER_PRODUCT(v1, v2)` |

**Exam trap:** Model name comes FIRST, text SECOND in EMBED_TEXT_* — reversed order is a common wrong answer choice.

### VECTOR Data Type
```sql
CREATE TABLE docs (
  id INT,
  content STRING,
  embedding VECTOR(FLOAT, 768)
);
```
Syntax: `VECTOR(<element_type>, <dimension>)` — element type is `FLOAT` or `INT`.

### Distance Function Semantics
| Function | Direction of 'similar' |
|---|---|
| Cosine similarity | HIGHER value = more similar (-1 to 1) |
| L2 distance | LOWER value = more similar |
| Inner product | HIGHER value = more similar (for normalized vectors) |

**Rule of thumb:** Use cosine similarity for text embedding retrieval when vector magnitude is not meaningful (most RAG use cases). Use L2 when magnitude matters.

### Retrieval Query Pattern
```sql
SELECT id, content,
       VECTOR_COSINE_SIMILARITY(embedding, ?) AS score
FROM docs
WHERE status = 'active'          -- filter FIRST
ORDER BY score DESC
LIMIT 10;
```
**Exam note:** Combine SQL `WHERE` filters with vector search so the engine prunes rows before computing distance — Snowflake computes vector distance as a per-row scan (no default ANN index like HNSW), so filtering matters a lot for performance at scale.

### Choosing Dimensionality & Model
- Lower dims (e.g., 768) → less storage, faster distance compute, may lose nuance.
- Higher dims (e.g., 1024) → better semantic capture, higher storage/compute cost.
- Match the embedding function to the model's native dimension: `EMBED_TEXT_768` for 768-dim models (e.g., e5-base-v2), `EMBED_TEXT_1024` for 1024-dim models (e.g., snowflake-arctic-embed-l-v2.0).
- Query and document embeddings MUST use the SAME model/dimension to be comparable.

### Common Exam Traps
1. Confusing cosine similarity direction (higher=better) with L2 distance direction (lower=better).
2. Reversing EMBED_TEXT_* argument order (model, text).
3. Computing distance over the entire table before applying SQL filters instead of filtering first.
4. Mixing embeddings generated by two different models/dimensions in the same similarity comparison — not comparable.
